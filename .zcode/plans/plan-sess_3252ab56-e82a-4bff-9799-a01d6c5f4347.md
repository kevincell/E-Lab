Implement DBMS module restructuring with SELECT/INSERT/UPDATE sub-questions:

## Data Models
1. Add SubQuestion model:
   - FK to Question (main_question)
   - type: SELECT/INSERT/UPDATE
   - Inherit Question fields: title, description, sample I/O, starter code, language_id, limits, etc.
   - starter_codes JSONField for multi-language support
   - is_active, is_mandatory
2. Add SubQuestionTestCase model (mirrors TestCase but FK to SubQuestion)

## Assignment Logic (services.py)
- get_or_create_module_assignment: Unchanged (still assigns main questions for DBMS)
- sync_assignment_completion: 
  - For DBMS modules: main question complete when all 3 subquestions completed
  - Check SubQuestion completion status instead of/ in addition to Question
- update_progress:
  - For DBMS modules: total = main_question_count × 3
  - completed = count of subquestions with accepted submissions

## Views (views.py)
- question_detail:
  - Detect DBMS module (category contains 'dbms') with subquestions
  - Get active subquestion from URL param (?subtype=SELECT) or default to first incomplete
  - Load subquestion data for display (title, description, starter_code, etc.)
  - Show tabs for SELECT/INSERT/UPDATE to switch subquestions
  - Form submission targets active subquestion
- module_level_detail: 
  - For DBMS modules, show main questions with subquestion completion progress
  - Each main question shows completion status of its 3 subquestions

## Forms (forms.py)
- SubmissionForm: Add hidden subquestion_id field
- Initialization: Load subquestion starter_code when applicable
- POST processing: Use subquestion_id to determine which subquestion answered

## Services
- choose_adaptive_questions: Unchanged (selects main questions for DBMS assignment)
- evaluate_submission:
  - Determine if evaluating subquestion (via submission.subquestion_id or context)
  - If subquestion: use subquestion's test_cases, language_id, time_limit, memory_limit_kb
  - Otherwise: use main question data (preserves non-DBMS behavior)
  - Track submission against subquestion for completion

## Templates (implicit via view changes)
- student/question_detail.html: 
  - Conditional rendering for DBMS subquestions (tabs/subquestion selector)
  - Display active subquestion content
  - Show completion status for all 3 subquestions
- student/module_level_detail.html:
  - For DBMS modules: show subquestion completion progress per main question

## Key Implementation Points
1. Backward compatibility: Non-DBMS modules work exactly as before
2. DBMS modules require main question + 3 subquestions (SELECT/INSERT/UPDATE)
3. Assignment count unchanged (still assigns main questions per difficulty)
4. Workload expands: 1 main question = 3 subquestions to complete
5. Completion: Main question complete only when all subquestions complete
6. Progress: Based on subquestion completion for DBMS modules
